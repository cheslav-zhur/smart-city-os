До этого юнита worker умел только claim job и записать пустые opinions. Теперь при наличии ключа он гоняет двухролевой граф, копит audit в памяти и пишет всё одной fenced-транзакцией — или ничего, если человек уже успел решить кейс.

1. Картина целиком

HTTP-ingest по-прежнему не ждёт модель. API только кладёт event / case / job. Мозг живёт в отдельном процессе python -m app.worker.

Пунктир к Operator: человек может нажать кнопку, пока graph ещё бежит. Тогда persist обязан отказать — это и есть смысл fence.

2. Три короткие транзакции

Долгий graph не держит DB-лок. Worker режет работу на три шага — это уже было в U3; U5 только подставил graph между claim и persist.

1. Claim — короткая txn: pending (или expired running) → running, bump lease_version, commit.
Почему отдельно: lease должен быть виден другим worker’ам до LLM-вызова.
2. Graph — своя session только на чтение (events/case) + файлы playbook. Opinions и audit копятся в памяти (RunContext), не в БД.
Почему не писать mid-graph: иначе после approve человека в audit долетели бы «призрачные» tool-строки без согласованных opinions.
3. Fenced persist — одна txn: оба opinion (или оба null) + audit rows + job terminal, но только если job_id + lease_version + status=running и case ещё open.
Fence = «я всё ещё владелец этой аренды». Steal или decide обнуляют право писать.

Где это в коде

# apps/api/app/jobs/loop.py — process_claimed_job
if not settings.llm_api_key:
    finish_empty_opinions(...)          # путь без модели
else:
    result = run_opinion_graph(...)     # память, не БД
    persist_job_result(                 # fence + оба столбца + audit
        ...,
        dispatcher_opinion=result.dispatcher_opinion,
        critic_opinion=result.critic_opinion,
        audit_rows=...,
    )

Lazy-import graph внутри if key: API-процесс, который импортирует jobs.service для cancel pending, не тянет LangGraph (KTD12).

3. StateGraph: две роли, разные allowlist

Не create_react_agent. Свой StateGraph: dispatcher крутит tools, потом critic — со своим списком tools. Bound names = allowlist: fly / approve / reject просто не зарегистрированы.

  • Dispatcher tools: read_recent_events, read_case, search_playbook, write_opinion
  • Critic tools: без read_recent_events — другой allowlist на node
  • write_opinion пишет только в RunContext; role должен совпасть с текущей нодой

Both-or-neither

Если graph закончился, но заполнился только один голос — в БД уходят оба null. «Уверенное» предложение модели = оба столбца non-null (KTD9). Timeout / нет ключа / exception → тоже null, кейс всё ещё approvable.

4. RunContext и timeout

Tools читают session/case через contextvars. Graph крутится в ThreadPoolExecutor с wall-clock timeout (25s < lease 30s), поэтому контекст копируется в поток — иначе tools не видят RunContext. 

# apps/api/app/llm/run.py
copied = contextvars.copy_context()
future = pool.submit(copied.run, _call)
future.result(timeout=timeout_seconds)  # 25s

Cancel потока после timeout не убивает уже идущий HTTP к Gemini — lease всё равно истечёт, другой worker сможет steal. Persist старого lease станет noop.

5. LLM-клиент: не «Google SDK», а совместимый endpoint

ChatOpenAI + LLM_BASE_URL на …/v1beta/openai/ + ключ AI Studio. Сегодня Gemini (gemini-3.6-flash), завтра другой compatible host — тот же код.

Модели Google снимают с полки: gemini-2.0-flash уже 404. Имя модели — env, не захардкоженный «навсегда» выбор продукта.

6. Audit: кто говорил

Operator audit как раньше (write_audit → actor из settings). Model/tool строки появляются только в fenced persist:

  • dispatcher / critic — action=model_call
  • tool:search_playbook и т.п. — action=tool_call

Консоль GET /cases/{id}/audit ещё в U6 — строки уже пишутся в таблицу.

7. Что сознательно не трогали

  • Ingest path и code rules — без LLM
  • Approve/reject и drone stub — только application code после человека
  • Redis / Celery / LangGraph checkpointer — нет
  • Compose worker service — это U7; пока python -m app.worker руками

8. Как читать файлы по порядку

  1. app/jobs/loop.py — оркестрация трёх шагов
  2. app/llm/run.py + run_context.py — память и timeout
  3. app/llm/tools.py — allowlist
  4. app/llm/graph.py — топология ролей
  5. app/jobs/service.py persist_job_result — fence + audit
  6. tests/test_agents.py — stub LLM, не live Gemini в CI

Если держать в голове одну фразу: модель предлагает текстом в памяти; БД меняется одним забором; летать по-прежнему может только человек.
