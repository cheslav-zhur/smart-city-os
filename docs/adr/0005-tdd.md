# 0005. Test-driven development

- Status: Superseded by [0006](0006-tests-without-tdd-on-mvp.md)
- Date: 2026-09-11

## Context

The MVP is a small loop with easy-to-lie-about behavior (idempotent ingest, one open case, no flight without confirm). Implementing first and “adding tests later” hides that. The console is harder to TDD than the API; the API is the contract.

## Decision

Feature work follows red → green → refactor:

1. Write a failing test that names the unit’s check (from the plan).
2. Write the minimum production code to pass.
3. Refactor only while tests stay green.

API units (U1–U3, U6) use pytest against the app or DB. Simulator (U4) tests the posted sequence or the rule with a test client. Console (U5) gets a thin component or contract test where cheap; the duty path is still proven through the API tests. U7 is a documented run, not a substitute for U2/U3 tests.

Do not add production code for a behavior that has no failing test yet, except glue that the current red test requires (settings, imports).

## Consequences

pytest (and later a web test runner) is a first-class dependency, not an afterthought. Plan units already list tests — those files are written first. Skipping red for “just a DTO” is not an exception if the DTO is the behavior.
