# v1

The first real shape. Same city loop as the MVP, with a thicker brain and a more honest backend — still one repository and one domain.

This file is a direction, not a frozen checklist. Several choices below are still open.

Process (open): start **TDD on the API loop** here if it still feels worth it. MVP only required tests, not red-first ([ADR 0006](../adr/0006-tests-without-tdd-on-mvp.md)).

## What it is

A short **shift** on one road: more than one kind of traffic fact, a case card that can hold more than one opinion, a human still the only one who can send a drone.

The console is an operations desk, not a chat and not a toy map.

## Likely in

- Event kinds on segment A: crash-like drop, speeding, slow stretch (jam).
- One optional resident text line into the same case («they crashed there») — not a citizen app.
- A playbook (a few markdown pages) the model can search.
- Narrow roles on the first duty-desk cut: dispatcher then critic, one pass each. Neither flies. A traffic voice is later v1, not that cut.
- A work queue so ingest does not wait on the model.
- Explicit case states (`open`, `approved`, `rejected`, `outdated`). Drone flight is a separate field, not a case status. Send and Dismiss only on `open`.
- Audit of operator actions **and** model/tool calls.
- Fallback: no key or model timeout → rule-only case, no confident flight proposal.

## Likely out

New sensor domains, a command-center map, a drone fleet, Kafka, Kubernetes, a separate vector database, a resident portal, closing a real road.

## AI

A **case file**, not a group chat.

Typical path (first duty-desk cut): rule opens a case → dispatcher (tools + playbook) → critic → one drone proposal → human. Not dispatcher-only, not three roles. Later v1 may add a traffic voice, a resident line, and a stub drone frame.

Router between roles is ordinary code unless they disagree.

## Backend

Patterns worth putting in on purpose, each with a one-line “why” in the README:

- Modular monolith (folders that could become services later).
- Idempotent ingest.
- Async jobs for the model graph.
- Case state machine.
- Tool allowlist; flight is code after confirm.
- Audit as data, not stdout.

This duty-desk cut uses a Postgres job table (same database, worker claims rows). Redis is not locked out — a later named cut may add it. Do not treat the current queue as an ADR.

Later (not the first duty-desk cut): DDD-shaped **code** domains on the API — explicit modules (events, cases, jobs, audit, …) with aggregates / application services inside the same process. Still one product domain and one repo. Not extra sensor domains and not a microservice split. Named as a follow-up in the [v1 duty desk plan](../../.compound-engineering/artifacts/plans/2026-09-16-001-feat-v1-duty-desk-cut-plan.md).

## Stack

Python, FastAPI, Postgres, LangGraph, one LLM gateway, Docker Compose. Playbooks as files; `pgvector` in the same Postgres only if file search is not enough. Thin console (list, card, audit).

Console HTTP client: locked in [ADR 0007](../adr/0007-console-openapi-client.md) — orval + TanStack Query from FastAPI OpenAPI (extends [0003](../adr/0003-mvp-stack.md)). Approve/reject responses use named Pydantic models. Browser `/api` vs FastAPI `/cases` stays a prefix rule, not a second API.

## Done enough

Compose up. Simulator keeps posting unique traffic incidents on segment A until `make stop`. At most one `open` case; a miss is `outdated`, not an operator dismiss. Card shows the proposal and kind. Reject leaves the drone idle and writes audit. Approve changes drone status and writes who allowed it. The loop still runs with no model key.
