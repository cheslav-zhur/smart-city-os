# v1

The first real shape. Same city loop as the MVP, with a thicker brain and a more honest backend — still one repository and one domain.

This file is a direction, not a frozen checklist. Several choices below are still open.

Process (open): start **TDD on the API loop** here if it still feels worth it. MVP only required tests, not red-first ([ADR 0006](../adr/0006-tests-without-tdd-on-mvp.md)).

## What it is

A short **shift** on one road: more than one kind of traffic fact, a case card that can hold more than one opinion, a human still the only one who can send a drone.

The console is an operations desk, not a chat and not a toy map.

## Likely in

- Event kinds on segment A: crash-like drop, speeding, slow stretch (jam).
- One optional resident text line into the same case («they crashed there») — not a citizen app.
- A playbook (a few markdown pages) the model can search.
- Narrow roles: traffic reads the tape; a critic may disagree; a dispatcher proposes **drone or not**. None of them fly.
- A work queue so ingest does not wait on the model.
- Explicit case states (open, waiting on human, drone in flight, closed).
- Audit of operator actions **and** model/tool calls.
- Fallback: no key or model timeout → rule-only case, no confident flight proposal.

## Likely out

New sensor domains, a command-center map, a drone fleet, Kafka, Kubernetes, a separate vector database, a resident portal, closing a real road.

## AI

A **case file**, not a group chat.

Typical path: rule opens a case → traffic agent (tools) → playbook lookup → optional critic → one drone proposal → human → if yes, a stub frame and a short look at the image.

Router between roles is ordinary code unless they disagree.

Open: how many roles in the first v1 cut (dispatcher only vs dispatcher + critic). Better to add a second voice when the first one is visible, not all at once.

## Backend

Patterns worth putting in on purpose, each with a one-line “why” in the README:

- Modular monolith (folders that could become services later).
- Idempotent ingest.
- Async jobs for the model graph.
- Case state machine.
- Tool allowlist; flight is code after confirm.
- Audit as data, not stdout.

Open: Postgres job table vs Redis when latency starts to hurt. Start with Postgres.

## Stack

Python, FastAPI, Postgres, LangGraph, one LLM gateway, Docker Compose. Playbooks as files; `pgvector` in the same Postgres only if file search is not enough. Thin console (list, card, audit).

## Done enough

Compose up. Simulator runs a messy few minutes (a false alarm and a real one). Card shows the proposal. Reject leaves the drone idle and writes audit. Approve changes drone status and writes who allowed it. The loop still runs with no model key.
